1. Concept — What NeuroBand Is, and Why Now

The HearMe stack already ships an active-trigger surface area: shake, voice safe-word, duress PIN, timer check-in, in-app SOS button. Every one of them assumes the user can act. The NeuroBand closes the last gap — the woman who is held still, gagged, or whose phone is just out of reach. Her body still leaks distress: heart rate spikes, skin sweats, skin cools, fingers clench. NeuroBand is a wrist-worn BLE band that captures those signals and hands them to the HearMe phone, which alone decides whether to fire SOS.

This implements §8 Biometric Wearable Layer of HearMe Hardware & IoT Strategy — Volume III. The strategy doc commits to the “physiological duress signature: any two of the five physiological signals firing together” rule. Volume IV is how it ships.

Architectural rule, unchanged from Volume III: the band is dumb. It samples, filters, and ships features. The phone owns all decision logic. A leaked GATT packet must reveal nothing; a stolen band must trigger nothing.

4. Reference Schematic & Power Domains

┌────────── 3.7 V LiPo (110 mAh) ──────────┐ │ │ ▼ ▼ TP4056 (USB-C) TPS62740 buck → 3.0 V digital rail │ │ │ ┌───────────────┼──────────────────┐ │ ▼ ▼ ▼ │ nRF52840 BMI270 IMU MAX30205 Skin T │ (BLE / MCU) (I²C addr 0x68) (I²C addr 0x48) │ │ MCP1700 LDO → 3.0 V *clean* analog rail │ │ │ ├──► MAX30102 (PPG) I²C 0x57 │ ├──► Grove GSR ADC pin P0.04 │ └──► MyoWare 2.0 ADC pin P0.05 │ └──► DRV2605L (haptic, I²C 0x5A) ──► LRA TTP223 cap-touch ──► P0.06 (IRQ)

Two separate 3.0 V rails are non-negotiable. The PPG and GSR analog front-ends are easy to poison with switching noise from the BLE radio. Buck for digital, LDO for analog, star-ground at the LiPo – node. Skipping this is the #1 reason DIY bio-bands false-trigger.

5. Firmware Architecture (Zephyr + NimBLE)

Zephyr RTOS with the NimBLE host. Nordic SDK is being deprecated; do not start a new project on it.

┌─────────────────────────────────────────────────┐ │ Sensor task 10 Hz │ │ ├─ MAX30102 → HR, HRV-RMSSD, IBI, SpO2 │ │ ├─ Grove GSR → tonic + phasic split (µS) │ │ ├─ MAX30205 → skin °C │ │ ├─ BMI270 → accel, gyro, motion class │ │ └─ MyoWare → sEMG envelope │ ├─────────────────────────────────────────────────┤ │ Edge filter (rolling 30-s window) │ │ ├─ HR baseline (Welford online mean+var) │ │ ├─ GSR phasic-tonic decomposition │ │ ├─ Skin-temp drift vs 5-min average │ │ └─ Motion classifier { still | walk | run } │ ├─────────────────────────────────────────────────┤ │ GATT publisher 1 Hz notify │ │ └─ packs into the 20-byte HearMe BioFrame │ ├─────────────────────────────────────────────────┤ │ Capacitive override task 50 Hz poll │ │ └─ writes silent_trigger char on triple-tap │ ├─────────────────────────────────────────────────┤ │ Crypto + counter per-frame │ │ └─ AES-CCM, monotonic 32-bit counter │ └─────────────────────────────────────────────────┘
The band ships features, not raw waveforms. That keeps BLE bandwidth low, battery healthy, and means a captured GATT packet contains a single byte of HR, not a 250 Hz PPG trace that could fingerprint the wearer.

6. BLE GATT — HearMe Bio Service

Custom 128-bit UUID base, four characteristics. All notify-and-write traffic is AES-CCM encrypted using a per-session key derived during pairing.

Characteristic UUID suffix Direction Payload
bio_frame …8001 Notify, 1 Hz 20 B: [seq u16][hr u8][hrv_rmssd u8][spo2 u8][gsr_us u16][temp_c10 i16][motion u8][semg u8][battery u8][flags u8][counter u32]
silent_trigger …8002 Notify 1 B: bit0=triple-tap, bit1=auto-fired, bit2=tamper
command …8003 Write Calibrate / haptic-buzz / OTA-handoff / sleep
device_info …8004 Read Firmware version + serial (no PII)

Field encoding rationale: HR fits in u8 up to 255 bpm; skin temp is stored as °C×10 in i16 for ±0.1 °C resolution; GSR in µS×100 as u16 covers 0–655 µS which spans every realistic skin response. The trailing u32 counter is the monotonic value Volume III mandates for replay protection on every GATT write.

7. Pairing, Crypto & Replay Protection

  1. Each band ships with a unique 12-character PSK printed on a sticker on the inside of the strap.
  2. HearMe app scans, finds the band, prompts for the PSK.
  3. App and band perform ECDH key exchange over BLE, mixing the PSK as a salt to defeat MITM.
  4. The derived 128-bit session key feeds AES-CCM on every frame thereafter.
  5. The 32-bit counter increments per frame; the phone rejects any frame whose counter is ≤ the last accepted value.
  6. Re-pair clears the counter and rotates keys.
No “0000”-class PINs. Volume III explicitly forbids weak pairing. PSK + ECDH is the only acceptable scheme; reuse the implementation you ship for the Tier-1 BLE Clip so a single audit covers both products.

8. Signal Fusion — The 2-of-5 Duress Rule

This is the only piece of intelligence on the phone. It must live in the app, not in firmware, so you can A/B-test thresholds across the user base without re-flashing every band.

markers per 30-s window (each is 0 or 1): M_hr = HR > baseline + 25 bpm AND motion ∈ { still, walk } M_gsr = GSR phasic peak > 1.5 × tonic-baseline M_temp = skin-temp drop > 0.4 °C from 5-minute average M_spo2 = SpO2 < 92 % (crash / unconsciousness fallback) M_semg = sEMG envelope > 2 σ above resting (clenched fist sustained > 4 s) if popcount(markers) >= 2 AND not in_workout_mode AND time_since_calibration > 24 h: fire silent SOS
MarkerSensorWhy it fires during distress
M_hrPPGSympathetic surge — fear response spikes HR even when the person is held still.
M_gsrGSRSweat-gland activation is the most reliable panic biomarker; can’t be voluntarily suppressed.
M_tempThermopilePeripheral vasoconstriction during shock drops skin temp before core temp moves.
M_spo2PPG (red+IR)Falls when restraint compromises breathing or after physical assault.
M_semgsEMGClenched-fist tension — the involuntary fight-or-flight muscle response.
The motion gate is what makes this safe to ship. Without it, two markers will fire constantly during a run. The Volume III rule explicitly says “heart-rate spike with no motion.” Honour it.

9.3 Provider wiring

Mirror the existing ShakeBridge pattern in providers/HearMeProvider.tsx:

function NeuroBandBridge({ enabled, onDuress, onSilentTrigger }: Props) { useEffect(() => { if (!enabled) return; const sub = NeuroBand.subscribe((frame) => { const verdict = fuse(frame); // 2-of-5 rule if (verdict === 'duress') onDuress(); if (frame.flags.tripleTap) onSilentTrigger(); }); return () => sub.remove(); }, [enabled, onDuress, onSilentTrigger]); return null; }

Both handlers route into the existing executeSos() — but with skipSosConfirm = true and sirenEnabled = false for genuinely silent operation. Do not open an Alert dialog on duress — that defeats the entire point.

10. Evidence Trail & Cloud Sync

When NeuroBand fires SOS, append a 'bio' evidence item alongside the existing location stamp. Extend lib/evidence-locker.ts:

session = addEvidenceItem(session, { type: 'bio', uri: null, text: `NeuroBand duress: HR=${hr} bpm, GSR=${gsr} µS, ` + `temp=${temp.toFixed(1)} °C, motion=${motion}`, lat, lon, alertId: null, tags: ['sos', 'neuroband', `markers:${marker_bitmap}`], });

This gives you the legal chain — physiological signature → timestamp → location → cloud sync → hash-chain anchor — already documented as court-admissible in Volume III §11. The marker bitmap (e.g. markers:01101) is what forensics will care about: it explains why the system fired, not just that it fired.

11. Calibration, Workout Mode & False-Positive Control

MechanismWhat it doesHow it’s exposed
24-hour calibration window For the first 24 h after pairing the band streams data but cannot fire SOS. Establishes per-user HR / GSR / temp baselines. “Learning your body” onboarding card on the NeuroBand screen.
Workout mode Disables the fusion engine for a user-set duration (default 1 h). Cap-touch override still works. One-tap toggle; auto-prompts when IMU detects sustained run pattern for > 5 min.
Sensitivity dial Switches threshold from 2-of-5 (normal) to 3-of-5 (low) or HR±15 bpm (high). neuroBandSensitivity in Settings.
Confirm-window for borderline events If exactly 2 markers fire but motion class is ambiguous, the band buzzes once and waits 10 s for the user to swipe-cancel. Haptic; auto-fires if no input. Volume III calls this “reassurance loop — felt, not seen.”
Adverse-event log Every fire / cancel / mis-fire records a row to a local debug log. Used to retune thresholds. Hidden behind a long-press on the NeuroBand screen header.

12. Privacy, Security & Regulatory Posture

  • PSK + ECDH pairing, AES-CCM on every frame, monotonic 32-bit counter — not a fixed PIN.
  • The band stores no PII. Serial number only. A confiscated band reveals nothing about its wearer.
  • Firmware OTA images are signed with the HearMe ed25519 key — same key already mandated for the BLE Clip.
  • Raw waveforms never leave the band. Only computed features. A subpoena to the cloud cannot return PPG traces because they were never uploaded.
  • The HearMe app shows a persistent “NeuroBand is monitoring” status whenever the engine is armed. Hidden surveillance is a liability, not a feature.
  • Bio-data classification: under India’s DPDP Act 2023 this is sensitive personal data. Store in Supabase with row-level security keyed to the user’s auth ID, encrypted at rest.
  • Medical-device positioning: the band is a safety wearable, not a medical device. The app must not advertise diagnostic claims (e.g. “detects atrial fibrillation”) without CDSCO clearance.

13. Build, Test & Validation Order

  1. Wire the breadboard. nRF52840-DK + MAX30102 + Grove GSR + BMI270 on jumpers. Skip the enclosure entirely until step 7.
  2. Stream BioFrame to nRF Connect mobile. Verify the 20-byte struct decodes cleanly. Walk around, check counter increments, check no dropped notifies.
  3. Add lib/neuroband-ble.ts with a debug screen that just plots live HR / GSR. Ignore fusion; this is plumbing only.
  4. Wear the breadboard for 24 h yourself. Capture HR baselines (rest, walk, run) and GSR baselines (cool, warm, sweaty). This is the dataset that tunes the thresholds.
  5. Tune the fusion thresholds with the captured data. The values printed in §8 are starting points, not gospel. Expect to move them ±20%.
  6. Stage the duress trigger with a benign side-effect first: haptic buzz + console log. Do not wire executeSos() yet.
  7. Wire the real SOS path. Run the pre-flight: workout-mode lockout, calibration check, motion gate, sensitivity dial. Test with a tame contact list.
  8. Add the capacitive override last. It’s the easiest path; if it’s present in step 1 you’ll lean on it and never validate fusion.
  9. PCB spin only after fusion accuracy is stable on breadboard. EasyEDA + JLCPCB ~₹6,000 for 5 prototypes.
  10. Field pilot with 10 users for 2 weeks. Collect adverse-event log. Re-tune. Then ship.
