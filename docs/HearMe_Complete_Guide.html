1 · What HearMe is

HearMe is an integrated personal-safety toolkit. The phone app is the user-facing surface; the optional NeuroBand wristband adds physiological detection of duress that doesn't depend on the user being able to reach for a phone. Supabase provides authenticated, row-level-secured cloud sync for evidence, and an opt-in dashboard surface lets vetted partner organisations help dispatch responders.

The three things HearMe is built to do

Detect

Detect distress automatically — voice triggers, biosignal fusion, behavioural anomalies, fall and crash detection, acoustic events, BLE stalker scanning, and isolation scoring.

Capture

Capture evidence the moment it matters — pre-roll audio, photos, location pings, biosensor frames — all chained, signed, and time-stamped on-chain.

Reach

Reach trusted people fast — SMS to all contacts, ack-aware tier escalation, encrypted live-share, witness mode, community SOS mesh, and PSAP hand-off where regulations allow.

Design principles

  • Phone is the source of truth. The phone runs detection, the band augments. If the band is down or absent, the app degrades gracefully.
  • Cloud is the destination, not the operator. Evidence is encrypted on the device, hashed locally, then pushed. Supabase never sees plaintext audio.
  • Court-grade chain of custody. Every captured artefact is hashed, chained, signed with a device-bound Ed25519 key, and anchored to the Bitcoin blockchain via OpenTimestamps.
  • Hostile-environment design. Disguise mode, decoy lock, force-unlock detection, anti-uninstall, airplane-mode counter — every adversarial path is closed.
  • Honest where adapters are needed. When a feature genuinely needs a native module / vendor SDK / hardware (PSAP API, satellite SDK, ML Kit), the JS layer reports "not available in this build" — never returns silent success it didn't earn.
The shape of this guide. Sections 4–7 cover the baseline app shipped at version 1.0. Sections 8–15 cover the 35 advanced modules added in the subsequent rev. Each advanced module includes its purpose, why it exists, and the file path of the implementation.

2 · High-level architecture

Three actors: the band, the phone, and the cloud. Detection happens on the phone, augmented by the band. Cloud sync happens only when an event fires.

Data residency

  • On-device only: raw audio, draft evidence sessions, voiceprint, signing keys, duress PIN, cycle-log, voice-trigger challenges.
  • On-device, then encrypted to cloud: finished evidence sessions (file content + chain hash + signature + OTS receipt).
  • Cloud-only ephemeral: live-share ciphertexts (E2E AES-GCM), guardian-relay ack messages, community-mesh beacons (auto-prune on TTL).
  • Public RPCs: incident heatmap (k-anonymous aggregate, never per-user), evidence_attestation lookup (chain hash + signature + OTS receipt only).

7 · NeuroBand wearable integration

The NeuroBand is an optional Bluetooth wristband running Zephyr firmware on an nRF52840. It exposes a single GATT service over which it streams a 20-byte BioFrame at 1 Hz and emits sparse silent-trigger / tamper events. The phone-side fusion engine combines those signals with phone sensors to detect duress with high specificity.

BioFrame contents

FieldTypePurpose
sequint16Per-connection rolling counter for ordering.
hruint8Heart rate (BPM).
hrvRmssduint8Heart-rate variability proxy.
spo2uint8Blood-oxygen %.
gsrUsuint16Skin conductance in µS.
skinTempCint8Skin temperature, fixed-point °C.
motionuint8still / walk / run / fall / unknown.
semguint8Surface-EMG envelope (clench detection).
batteryuint8Band battery %.
flagsbitscharging · tamper · low-battery.
counteruint32Replay-protection monotonic counter.

Fusion engine

The §8 Volume-III duress signature: any two-of-five physiological signals firing together — while motion is still or walk — fires a verdict. Each marker has a sustained requirement (e.g. HR must be elevated for ≥4 s) so single-frame sensor noise can't trigger SOS. Sensitivity is adjustable; workout-mode lockout suppresses fires while exercising.

five markers ─► per-marker fired? (instantMarkers) │ ▼ sustained-window memory (SUSTAIN_REQUIRED per marker) │ ▼ fire = sustainedCount ≥ requiredCount (sensitivity-tuned)

Mock mode

A synthetic BioFrame stream lets the entire UI + fusion engine run without paired hardware. Three modes — calm, active, duress — exercise the rule transitions.

lib/neuroband-ble.ts · lib/neuroband-fusion.ts · lib/neuroband-pairing.ts · lib/neuroband-storage.ts · firmware/neuroband/

8 · Advanced features — Phase A · evidence foundation

Phase A — Evidence foundation

Make every captured byte court-defensible and recoverable.
1Continuous pre-roll bufferSHIPPED

Always keeps the last 30 seconds of audio on disk. When SOS fires, the buffer is attached to the evidence session retroactively — we capture what happened before the trigger, not just after. Implementation rotates 10-second WAV chunks; a native circular buffer can drop in via the backend slot.

lib/preroll-buffer.ts
2Cryptographic chain-of-custodySHIPPED

Every uploaded evidence session is signed with a per-device Ed25519 key (private key in SecureStore, public key uploaded to Supabase) and the chain hash is anchored to the public OpenTimestamps Bitcoin calendar. Verifiers can prove "this evidence existed by block N" without trusting HearMe.

lib/evidence-signing.ts · supabase/evidence-signatures.sql
3Dead-man's switch uploadSHIPPED

Persistent retry queue with reachability probing. If primary upload fails, registered relay backends (BLE-paired peers, alternate transports) get a chance. After three failed attempts contacts are SMS-notified that evidence is pending so the device can be physically recovered.

lib/evidence-deadman.ts
4Lawyer / NGO export packageSHIPPED

One-tap signed bundle: manifest.json with chain hash, signature, public key, OTS receipt, and signed Supabase URLs for every media item; plus a standalone summary.html a legal reader can open offline. The recipient's verification recipe is included inline.

lib/evidence-export.ts

9 · Advanced features — Phase B · trusted network

Phase B — Trusted network

Reach the right person, fast — with proof of receipt.
5Encrypted live-share sessionSHIPPED

End-to-end AES-GCM stream of location (and optional audio chunks) over Supabase Realtime. The AES key lives only in the URL fragment after the # — Supabase only ever sees ciphertext + the channel id. Recipients send back ack receipts so the user knows who actually opened the link.

lib/live-share.ts
6Guardian relay (ack-aware fan-out)SHIPPED

Contacts have priority tiers. Tier 1 is messaged immediately; if no ack within T seconds, Tier 2 is messaged next, then Tier 3 — and the configured emergency number (e.g. 112) is dialled as the last-resort step. Acks come over a per-alert Realtime channel.

lib/guardian-relay.ts · lib/types.ts
7Two-way duressSHIPPED

A trusted contact can send "are you safe?" — the user's band buzzes a covert 3-pulse pattern. The user replies via band triple-tap (safe) or button (unsafe), or silence for 60 s auto-escalates to SOS via the relay.

lib/two-way-duress.ts
8Witness modeSHIPPED

The user shows a one-time QR; whoever scans joins an E2E-encrypted session and their phone records audio + location chunks straight into the user's evidence locker — anonymously to the user, signed by the witness's device.

lib/witness-mode.ts
9Community SOS meshSHIPPED

Opt-in: when SOS fires, a short-lived geo-anonymous beacon is published. Other HearMe users within R metres get a non-blocking "someone nearby just sent SOS" banner; they can offer "on the way" with their location. Beacon ids rotate; recipients are anonymous unless they explicitly identify.

lib/community-mesh.ts · supabase/community-mesh.sql

10 · Advanced features — Phase C · detection & sensing

Phase C — Detection & sensing

Notice the threat before the user has to.
10BLE stalker scanSHIPPED

Detects covert personal trackers (AirTag, Samsung SmartTag, Tile, Google Find-My) that have followed the user across distinct locations for ≥30 minutes. Manufacturer-data parsing handles MAC rotation; persistent sighting log reaches across app sessions.

lib/stalker-scan.ts
11Isolation scoreSHIPPED

Combines BLE neighbour count, ambient dBFS, lux (Android), speed, hour-of-day, and safe-zone membership into a 0–100 score. High score auto-raises fusion sensitivity and prompts the user to start journey monitoring.

lib/isolation-score.ts
12Driver / passenger classifierSHIPPED

Heuristic on speed + accelerometer / gyroscope variance + touch rate, classifying the user as driver, passenger, on-foot, idle. The journey monitor uses this to soften false alarms when the user is clearly a passenger.

lib/drive-passenger.ts
13Phone-tamper detectionSHIPPED

Triple-coincidence detector: screen-off without a recent touch + accelerometer shock + simultaneous network loss within 6 s ⇒ silent SOS. Two-of-three only ⇒ heightened-alert banner.

Network watchdog raises a banner on sustained connectivity loss. Pluggable transport adapters (Meshtastic LoRa, Garmin inReach, sat-phone bridges) drop in via the backend interface; iOS satellite-SOS is surfaced as a help-text prompt because Apple gates the trigger to the side button.

11 · Advanced features — Phase D · resilience

Phase D — Resilience & adversarial robustness

Stay useful when the attacker has the phone.
15Decoy lock screenSHIPPED

Different from disguise mode (calculator) and duress PIN (reversed). The decoy lock is a fake lock screen the user can flip on at any moment: it shows "No Service", a draining fake battery, and rejects every input as "incorrect" — while silently firing SOS in the background.

lib/decoy-lock.ts
16Force-unlock detectionSHIPPED

Wraps expo-local-authentication with motion-aware verification. Samples accelerometer for 2 s before the bio prompt; if motion variance is high and failed bio attempts within window ≥ 2, the unlock is flagged as forced and silent SOS fires.

lib/force-unlock.ts
17Anti-uninstall guardADAPTER + RECIPE

JS adapter + a complete Android Device Admin recipe (Manifest + receiver + DPM calls). The duress PIN is the gate to disable. iOS path leans on Screen Time restrictions because Apple does not let third-party apps prevent uninstall.

lib/anti-uninstall.ts
18Airplane-mode counterSHIPPED

Detects simultaneous loss of cellular AND Wi-Fi within seconds of an accelerometer shock — the signature of someone toggling airplane mode after grabbing the phone. Escalates via a registered alt-modem backend (e.g. NeuroBand LTE-M, sat dongle) or the standard relay.

lib/airplane-counter.ts

12 · Advanced features — Phase E · on-device intelligence

Phase E — AI / on-device intelligence

Smarter detection without sending data to a server.
19Threat-context classifierSHIPPED

Multi-modal score combining transcript, fusion verdict, isolation, drive context, acoustic events, time of day, and safe-zone membership. The default is a transparent rule-based heuristic; an on-device LLM (Gemma 2B / Phi-3-mini via mlc-llm) can drop in via the backend interface.

lib/threat-classifier.ts
20Acoustic event detectionSHIPPED

Default envelope detector identifies scream, shout, thud, silence from the meter signal. A YAMNet TFLite backend slot accepts the same event shape; the recipe (audio windowing, ontology mapping, native dep list) is bundled in the source.

lib/acoustic-events.ts
21Speaker diarizationSHIPPED

Splits an evidence audio clip into "user vs other" segments. Default uses RMS + zero-crossing-rate + spectral centroid against an enrolled voiceprint stored in SecureStore. Adapter slot accepts pyannote / TitaNet / ECAPA-TDNN backends.

lib/diarization.ts
22Auto-redactionADAPTER + RECIPE

Face / plate / PII blur on captured photos. Refuses to silently return originals — the no-op default reports { ok: false, reason: "noBackend" }. ML Kit (Android) and Vision (iOS) recipes are inline; manual-region blur is supported the same way.

lib/auto-redaction.ts
23Deepfake voice-trigger guardSHIPPED

Wraps voice-trigger with a voiceprint-match step (re-using the diarization enrolment) and an optional per-session challenge word. A failed challenge demotes the response from "act-loud" to "prompt-user" — never silently rejects, because false negatives in safety code are worse than false positives.

lib/voice-trigger-guard.ts

13 · Advanced features — Phase F · NeuroBand expansion

Phase F — NeuroBand expansion

Make the wearable smarter and more personal.
24HRV-based stress baselineSHIPPED

24 circadian-hour buckets, each tracking RMSSD mean/variance via Welford's online algorithm. The current frame's z-score against the right hour bucket gives a 0–100 stress index that fusion uses to dynamically adapt sensitivity.

lib/hrv-baseline.ts
25Cycle-aware sensitivitySHIPPED

The luteal phase shifts resting HR up ~5 BPM and HRV down ~15%, which produces chronic false-positive runs in fixed-threshold fusion. The module ships a privacy-preserving manual log + a HealthKit / Health Connect adapter slot, then emits an adjustment {phase, hrThresholdOffsetBpm, hrvBaselineMultiplier}.

lib/cycle-aware.ts
26Band-side LED / haptic codesSHIPPED

Extended single-byte command protocol: 0x10–0x1F acks, 0x20–0x2F warnings, 0x30–0x3F silent statuses. Each code maps to a distinct vibration pattern + LED colour/pulse so the user feels-through-the-wrist what's happening (SMS sent, contact opened, helper on the way…) without looking at the phone.

lib/band-feedback.ts
27Group band roamingSHIPPED

One account, multiple bands — kid + parent + grandparent. Per-member geofence, group realtime channel for fusion fires from any band, role labels (self / kid / parent / partner / sibling / friend / grandparent).

lib/band-roaming.ts

15 · Advanced features — Phase H · operational

Phase H — Operational

Keep the system honest, observable, and self-healing.
33Anonymous incident heatmapSHIPPED

Each fired SOS appends a 3-decimal-place bucketed ping (~110 m grid). The public RPC heatmap_at(lat, lon, radius) aggregates per cell with a k-anonymity floor — cells with fewer than K hits collapse into a "rare" bucket. Users can erase their own contributions.

lib/incident-heatmap.ts · supabase/heatmap.sql

Nine non-destructive probes — SMS path, contacts validity, GPS accuracy, mic, biometric enrolment, NeuroBand link recency, Android battery optimisation hint, Supabase auth, device battery level. Runs weekly and on demand; surfaces broken pipes BEFORE an emergency.

lib/self-test.ts

Schema for partner organisations (NGOs, campus security): organisations, members, user-org links with explicit per-scope consent, and an immutable audit table. Two security-definer RPCs (responder_active_alerts, responder_user_evidence) enforce membership + consent + audit-on-read. Architecture spec lives at docs/responder-dashboard.md; the dashboard itself is a separate Next.js project.

17 · Privacy & security model

Identity

  • Multi-path auth (PIN, biometric, Aadhaar OTP, demo PIN). Losing one path doesn't lock the user out.
  • Per-device Ed25519 signing key generated on first use, persisted in SecureStore (Keychain on iOS, EncryptedSharedPreferences on Android). Never leaves the device.

Data at rest

  • SecureStore: duress PIN, signing private key, voiceprint enrolment, smart-home endpoint secrets, voice-trigger challenge, NeuroBand session key + PSK.
  • AsyncStorage: contacts, settings, evidence sessions, alert history, NeuroBand baselines / event log, cycle log, dead-man queue, stalker sightings.
  • Supabase Storage (private bucket): uploaded evidence files. Access only via signed URLs scoped to the owning user.

Data in transit

  • Live-share & witness mode: AES-256-GCM with per-session keys. The key lives in the URL fragment (after #) — it never reaches a server.
  • Two-way duress & guardian relay acks: Supabase realtime broadcasts. Payloads are E2E-encrypted where they carry sensitive data; ack signals carry only contact id + name.
  • Community mesh: opt-in beacons carry only lat/lon/severity + a rotating opaque id. No user identity or device id.

Tamper evidence

  • Every evidence item carries a SHA-256 content hash.
  • Items are linked: chain[i] = SHA256(chain[i-1] || contentHash[i]). Any edit invalidates every later hash.
  • The final chain hash is signed with the device Ed25519 key and submitted to a public OpenTimestamps Bitcoin calendar. Within ~6 hours the OTS receipt upgrades to a Bitcoin block attestation that anyone can verify offline.

Row-level security (Supabase)

  • Every table that holds user data has RLS enabled. Policies restrict select / insert / update to auth.uid() = user_id.
  • Storage policies are file-path-aware: a user can only write to <their-uid>/... paths in the evidence bucket.
  • Public RPCs (heatmap_at, evidence_attestation, responder_*) are security definer and enforce explicit consent / k-anonymity / role gating before returning rows.

Adversarial robustness

  • Disguise mode (calculator) hides the app from a casual snoop.
  • Decoy lock screen + duress PIN deflect an active attacker.
  • Force-unlock detection escalates if struggle motion is detected during a bio prompt.
  • Anti-uninstall guard (Android Device Admin) requires the duress PIN to remove the app.
  • Phone-tamper + airplane-mode counters detect attempts to silence the phone.
  • Deepfake voice-trigger guard requires a voiceprint match, demotes (never silently rejects) on failure.

EXPO_PUBLIC_SUPABASE_KEY=<anon-key>

Use the anon key, not the service-role key. RLS gates every table.

  1. supabase/setup.sql — base tables & profile RLS

19 · Adapter pattern (production-grade strategy)

Several advanced features genuinely need code that is not in the JS / Expo surface — PSAP REST clients, Wear OS bridges, Android Device Admin, ML Kit face detection, on-device LLMs, satellite SDKs, Meshtastic protobufs. Rather than ship fake "production" code, each of those modules implements the adapter pattern:

lib/<feature>.ts ──────────────────► ┌────────────────────┐ │ exposes interface │ Default backend: │ │ + JS-side glue │ heuristic / mock │ │ + Supabase / Expo plumbing │ / Supabase │ │ └────────────────────┘ └──► register({ backend }) ───────► drop-in real impl (TFLite / native / vendor SDK)

The app calls lib/<feature> in one place. The default backend is a working, useful approximation — or, where there is no useful default (e.g. face detection), an honest no-op that refuses to claim success it didn't earn. Replacing it with the real thing is a single register({ backend: realImpl }) call from a custom dev client.
